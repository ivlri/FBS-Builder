# 1. Текущие проблемы

## 1.1 Ошибки в результатах

### 1. Нарушение перевязки (Wall 1)

Пример:

L0 – 3 блока (900)  
L1 – 2 блока (900)  

Первые блоки стоят строго друг над другом → отсутствует смещение швов → перевязка нарушена.

**Причина:**
- `ContextBuilder` фактически не обеспечивает корректную сетку перевязки.
- `bonding_left` и `bonding_right` не используются в `FBSBuilderEnv`.
- `build_grid()` вызывается только внутри `FBSBuilderEnv`.
- `build_grid_with_bonding()` является копией `build_grid()`.

**Вывод:**  
Логика перевязки реализована формально, но не встроена в реальные ограничения среды.

---

### 2. Пересечение блоков разных стен

Пример:

Wall 1 L1 | 4(1800), 3(1200)  
Wall 2 L1 | 4(1800), 3(1200)

Блоки пересекаются в общей зоне 300 мм.

**Причина:**
- ContextBuilder не резервирует общую зону строго.
- Оптимизатор игнорирует геометрию ради увеличения reward.
- Нет жесткого запрета на пересечение блоков.

**Вывод:**  
Общая зона должна быть заранее распределена по слоям между стенами до запуска RL.

---

### 3. Локально неоптимальные раскладки (проблема RL)

Пример:

L1 | 3(1200), 0(300), 3(1200)  

Лучше:  
L1 | 0(300), 2(2400)

Проблемы:
- Лишние блоки.
- Монолит расположен не в оптимальной зоне.
- Нет стремления к уменьшению общего количества элементов.

**Вывод:**  
RL-агент соблюдает правила, но не оптимизирует структуру.

# 2. Архитектурные проблемы

## 2.1 ContextBuilder

### Текущие проблемы

1. `build_grid()` используется только в `FBSBuilderEnv`.
2. `bonding_left` и `bonding_right` фактически бесполезны.
3. `build_grid_with_bonding()` дублирует `build_grid()`.
4. Логика выбора типа chess-pattern реализована неявно и запутанно.

### Что должно быть

ContextBuilder должен выполнять только одну задачу:

- Определять тип chess-pattern для каждой связи.
- Формировать маску разрешённых ячеек (0 / x) для каждой стены и каждого слоя.
- Гарантировать отсутствие пересечений.
- Гарантировать отсутствие монолита в зоне перевязки.

ContextBuilder НЕ должен:
- Запускать RL.
- Считать reward.
- Делать beam search.
- Проверять циклы графа.

---

## 2.2 BondingOptimizer

Сейчас делает сразу три вещи:

1. Строит граф, проверяет циклы, выбирает стратегию.
2. Выполняет DP / beam search.
3. Запускает RL и вычисляет метрики.

Это нарушает принцип разделения ответственности.

### Предлагаемое разделение

#### 1. GraphSolver
- Строит граф связей.
- Проверяет, является ли граф деревом.
- Выбирает стратегию (DP или beam).

#### 2. PatternSolver
- Подбирает варианты chess-pattern.
- Возвращает assignments.

#### 3. LayoutEvaluator
- Запускает RL.
- Считает глобальные метрики.
- Возвращает WallResult.

# 3. Логика Chess-Pattern

## 3.1 Общая зона

Wall 1 и Wall 2 — физически разные стены.  
Общая зона равна min(толщина стен).

Пример: 300 мм.

В этой зоне:
- Блоки не должны пересекаться.
- Монолит запрещён.
- Нужно выбрать, какая стена владеет зоной в конкретном слое.

# 4. Ограничения на монолит

### Запрещено:

- Монолит в зоне перевязки.
- Монолит под монолитом.

### Разрешено:

- Монолит в свободном торце.
- Монолит при значительном выигрыше по общему качеству.

### Приоритет критериев:

1. Минимизировать общее количество блоков.
2. Минимизировать количество монолита.
3. Минимизировать количество торцевых монолитов.
